Option B, “Carry the Message”, as a WordPress site

The owner chose Option B and asked for it as a WordPress theme, with an easy admin interface for the lists that change. This build is a block theme for the look, a small site plugin for the data and the admin forms, and a must-use plugin for security. The public pages match the mockup closely; the changing facts are kept in plain wp-admin forms, and the page layout is locked.

Where it stands. Built and tested on a local WordPress 7.1.2 site (PHP 8.4) with the round-3 content, “today” pinned to Sat, Sep 26, 2026. Three reviewers scored it before a fixer round: fidelity 9, editing 6, code and security 7. The fixer closed all 9 must-fix items. Nobody has re-scored it since, and the launch gate (the main editor doing the five jobs unaided) hasn’t run.

The approach in brief

Three pieces, so the data survives a theme change and deactivating the site plugin can’t switch security off. No build step: plain PHP, JSON, CSS and a few small scripts.

Theme: the look

theme/spokares/

  • B’s site.css ported nearly verbatim; B’s colours, type scale and spacing in theme.json; fonts self-hosted
  • Header, footer and members sub-nav as template parts editors can’t reach
  • Page patterns for Home, How it works and About; templates for the three members pages
  • Two fixed design blocks: the seal lockup and the message-path figure

Site plugin: data and editing

plugins/spokares-core/

  • Events and Documents post types; rota, net, meeting and tile settings
  • wp-admin forms, a “Site tasks” dashboard and the ARES Editor role
  • Seven dynamic blocks (events, net, meetings, docs, toc, last-reviewed, asof) that print B’s markup
  • The layout lock: the server refuses page saves that change anything but words

Must-use plugin: the floor

mu-plugins/spokares-hardening/

  • XML-RPC off, user enumeration blocked, feeds and author pages 404
  • Security headers, upload allowlists, DOCX/XLSX inspection, EXIF stripping
  • Two-factor enforcement, authenticated SMTP, the old-URL 301/410 map
  • Can’t be switched off from wp-admin (the old site was hacked)
  1. Editor fills a formNet rota, Events, Regular meetings, Documents or Hub tiles. Guard rails check call signs, phone numbers and never-publish words.
  2. WordPress stores itAs an event or document post, or a small settings option. One home per fact.
  3. A block renders itOn every page load, for today in Pacific time. Past events drop off; “Happening now” is worked out.
  4. Visitors see B’s markupComplete without JavaScript. Signed-in editors also see “Edit this list in …” links.

The five jobs

  • 1 · Post the rotamonthly · target 3 minDashboard › Update the rota › type a call sign, or pick Open / Not posted yet › Save rota. Undo last save if needed.
  • 2 · Add an eventtarget 3 minAdd an event › pick the kind › name, date, optional short line, where, tasks, links › Publish. Yearly repeats: Duplicate.
  • 3 · Cancel or move a meetingtarget 1 minCancel or move a meeting › tick Cancelled or set Moved to › Save.
  • 4 · Add or replace a documenttarget 3 minAdd a document › name, section › tick the Privacy check to unlock the file chooser › Publish. Replace keeps the same link and removes the old file.
  • 5 · Change page wordstarget 5 minDashboard › Home › click and type › Save. The server refuses anything but word changes.

The admin, workflow by workflow

Screens as the ARES Editor sees them, unless marked. From wordpress/shots/final/, taken after the fixer round. Scroll inside a frame to see the whole screen, or open it full size.

Start: the Dashboard, and the site while signed in

The only Dashboard card is “Site tasks”: one button per job, what’s due, and who to ask. On the site, each list has a small “Edit this list in …” link that only signed-in editors see.

Job 1: the net-control rota

Thirteen Tuesdays, notes filled in from the net rules. One choice per row; Winlink boxes only on Winlink nights; “Shows” repeats what the public will see. Only changed rows are saved, and Undo restores the last save.

Job 2: events and exercises

Kind first; the form then shows only the fields that kind needs and says where the event will appear. Our own Save box: no Preview, Visibility or publish date. The list opens on Upcoming.

Job 3: meetings

Editors cancel or move a single date. The regular pattern (week, day, time) is on Meeting rules, which only administrators or someone the EC names can open.

Job 4: documents and hub tiles

The file chooser is locked until the Privacy check is ticked, and nothing uploads until Publish. Replacing a file keeps the link and removes the old file from the web.

Job 5: page words in the block editor

Pages open with the site’s header and footer shown but not editable. Editors click and type. The inserter, Styles tab, Advanced panel and page status controls are hidden, and the server refuses any save that changes more than words.

Webmaster only: Net details

Repeater, tone, net time and net weeks. A live preview prints every sentence these facts produce, and saving asks for confirmation. An editor without the grant gets a plain “ask the webmaster” page instead of WordPress’s error.

Reviewer scores

Three independent reviewers worked on their own dev sites. The scores are out of 10 and were given before the fixer round; the “after” lines say what the fixer changed. Nobody has re-scored the build since.

9/ 10

Fidelity

Does it keep B’s feel? Pixel diffs of 13 views, plus 1024 and 768 wide and the phone menu.

  • Home and Documents identical at 1440 and 390; other pages within 60px in height.
  • Header, footer, sub-nav, library rail, chips and phone menu identical; self-hosted fonts render the same.
  • Every change is a documented WordPress constraint or a round-3 fix. “None of it breaks the feel.”

After the fixer round

  • Fixed: SET extra-form link, ShakeOut DYFI link, the “Open position” pill, the “Stand by” line breaks.
  • Still open: event abbreviations, W1AW/7 link span, the WSDOT form label, desktop jump-link placement, plain 404 and search pages.
6/ 10

Volunteer editor

Six jobs done as a new ARES Editor account, 80 screenshots, including trying to break it.

  • The four forms (events, rota, documents, net details) are strong: plain words, “See it on …” links, working guard rails.
  • Weak: page settings around the block editor let a volunteer take a page off the site (password, template, Quick Edit), and a few controls didn’t respond (disabled call-sign box, multi-paragraph paste).

After the fixer round

  • Fixed: password, date, status and template are now kept by the server; Quick Edit and bulk Edit gone; Save box can’t be hidden; call-sign box and paste work; a Where field; Dashboard “Add” and “Replace” split.
  • Still open: no separate “What to bring” field; the launch gate with the real editor.
7/ 10

Code, security and hosting

PHPCS WordPress-Extra, PHP 8.3 compatibility, Plugin Check, 36 admin screens, anonymous probes.

  • No REST routes or anonymous handlers, no direct SQL, late escaping, nonces and capability checks on every handler.
  • Anonymous REST 401, users 404, XML-RPC 403, security headers present; plugin set matches the plan.
  • Problems: orphaned document files findable by ID; CI gate failing; layout lock and event checks only held for UI edits; misleading “Save as draft”.

After the fixer round

  • Fixed: attachment pages 404; deleted documents take their file with them; CI passes 11/11; the lock now counts classes and inline styles; events re-checked on any publish.
  • Still open: /readme.html can only be denied at the web server.

Remaining issues and open questions

Nothing here blocks further testing. The first group blocks launch.

Before launch

  • Launch gate: AG7QP (or the first named editor) does the five jobs on the dev site with only the Editing guide, inside the target times. Every stumble becomes a fix.
  • Re-review of the editor experience after the fixer round (the 6 predates the fixes).
  • Two-factor sign-in tested on a real Enhance staging site; the ops scripts have only run against a fake host.
  • Round-3 blockers: the net-scripts link exposes the roster (D14); join@ isn’t live; the legal-basis text needs SCEM review; the role addresses, including webmaster@spokares.org shown in the admin, are proposals (D11).
  • An administrator reviews and publishes the 37 documents after the production import, and clears the “Needs checking” items.
  • Remove the footer’s “Mockup” line in the launch release; “Privacy (coming)” needs a privacy page.

Ask Verpex

  • Web server kind (Apache, LiteSpeed or OpenLiteSpeed) and whether .htaccess deny rules are honoured.
  • Is opcache.validate_timestamps on? If not, deployed PHP doesn’t load until PHP restarts.
  • A web-server deny for /readme.html and /license.txt; expose_php=Off.
  • /wp-content/updraft/ blocked and upload folders not listable.
  • Does panel WordPress SSO bypass 2FA? Snapshot retention? A written AUP OK for the document library.

Decisions for the owner, EC and AG7QP

  • WordPress as the one source for events, the rota and meetings (D9).
  • Who besides the administrators may change Net details and Meeting rules.
  • DOCX/XLSX uploads (inspected) or PDF only.
  • Grey hairline under members headings (per the round-3 review), or keep B’s red rule.
  • Keep showing the alternate repeater on How it works, or hide it.
  • The old-URL re-point table (D15) and who reviews documents at launch.
  • The members pages’ fixed lines (“Bring to every exercise”, “Not posted here”) are git changes for an administrator. Confirm, or name which should become form fields.

Known limitations

  • Editors can’t add sections, table rows or pages; that is administrator work.
  • Home never lists events, by design. There is no per-event “What to bring” field.
  • A published document with a problem goes back to Draft; events keep their live version instead (documents deferred).
  • A file saved with a Draft document is reachable by its exact random address.
  • Small fidelity gaps listed under Exercises and How it works; the 404 and search pages are plain.
  • Rota, meetings and tiles are options: database backups cover them, WordPress exports don’t.
  • After launch (P2): a rota paste box, a calendar feed, settings export, and page-sync.
