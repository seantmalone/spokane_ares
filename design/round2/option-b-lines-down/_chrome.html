Option B, "Carry the Message": canonical chrome

Copy these blocks verbatim into every page, in this order: head block, then at the top of <body> the sprite, the skip link and the header; the page's <main id="main">; then the footer and the two script tags. Read DESIGN.md for the rules. This file is a reference, not a page of the site.

Active state (read this first)

  • Primary nav: put aria-current="page" on the current section's link and on no other. Home page: on "Home". How it works: on "How it works". About: on "About ARES & ACS". Every members/*.html page: on "For Members". CSS draws the amber bar from the attribute; there is no active class to add.
  • Members sub-nav: put aria-current="page" on the current item only (Overview on members/index.html, Documents & downloads on documents.html, Exercises & events on exercises.html). "Forms" is a filter preset of the library (documents.html#forms); it never carries aria-current.
  • Paths: top-level pages use the "top-level" variants below. Members pages use the "members" variants (every link and asset gets ../, and <body data-root="../"> so site.js builds correct links).
  • Body classes: page-home, page-how, page-about, and members-page on all three members pages (it adjusts anchor offsets under the sticky members bar).
  • Do not add a "Member login" anywhere, and do not add any alert-level status badge.
  • Required anchors that other pages link to: about.html#for-agencies (footer and Home agency band), about.html#contact, #licensing, #who-we-serve, #agreements; how-it-works.html#follow-a-message (the story section) and #activation; members/documents.html#ares-application and #forms; index.html#join and #visit.
